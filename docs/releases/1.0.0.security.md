# Rasta 1.0.0 release security review

The Apple Silicon candidate includes the manager and all eight signed connections. Each connection matches its own signed feed and bundled package.

## Source review

- Compare the release trust configuration with the existing pinned Ed25519 key. Signed feeds bind versions, targets, architectures, archive sizes and SHA-256 hashes. Verify the full archive and the compact Library alternative against the matching engine. See `test/update-feed.test.js`, `test/update-channels.test.js`, `test/github-release.test.js` and `test/development-release.test.js`.
- Review the manager's settings and installation bridge and each host's bridge in their isolated fixtures. Check sender validation, connection scope, path and archive validation, cache isolation and explicit Launch. See `test/installer-architecture.test.js`, `test/desktop-connections.test.js`, `test/host-bridge.test.js` and the integration checks run by `tools/release-check.mjs`.
- Verify the Codex integrity update and T3 vendor integrity setting with disposable fixtures. Check that installation restores the original host after a failed stage and that removal restores only the selected connection. See `test/codex-native.test.js`, `test/installer-architecture.test.js` and `test/gui-uninstall.test.js`.
- Keep version ordering and verification intact. An installed version higher than 1.0.0 requires a manual installation of the manager. Library offers an explicit replacement using the pinned bundled feed and waits for Launch. Automatic update checks retain version ordering.

## Release evidence

Record the source commit, locked dependency and secret scan results, tool versions and fixture results in `security-checks.json` from `npm run release:check`. Record the per-architecture signatures, archive and DMG sizes, matching signed feeds and checksums with the build. Record the owner's native Library results against those exact hashes and independently verify the draft and public downloads before advancing Stable.

The previous native T3 investigation recorded repeated permission prompts for Desktop workspaces. Recheck T3 with the candidate before recording native acceptance. Run the Stable Library check after publication.
